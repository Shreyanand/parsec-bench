# Tasks

200 tasks over five simulated services and 20 tools. Each asks a
question an operator would put to parsec, about a world small enough to read in
full in the task's `seeds/`. The baseline means below come from the single
measured run described in [`BASELINE.md`](BASELINE.md), over the 194
tasks that have a valid sample.

## Categories

Every task is classified on five axes. All five can be read from its files: the
first three from `task.toml`, the last two from `tests/expected.json`.

**Primary service**, the service the question is about. Its name is the second
field of the task id.

**Kind**, the shape of the problem:

- **happy**: the straightforward path. Find the record, follow the chain, report
  what the data says.
- **trap**: a documented wrong move is available and penalised. That move might
  be a same-named decoy on another cluster, a tempting surface cause, a stale
  status field, a wrong repository owner, or a counter whose name overstates what
  it counts.
- **negative**: the honest answer is a refusal or a non-finding. There is nothing
  to delete, no free account left, or no such host.
- **chain breaks**: an intermediate hop returns something unusable, and the
  agent must notice and adapt instead of reasoning over it.

## Reading one task

Start with `instruction.md`, which is exactly what the agent is given. Then read
`provenance.md`, which carries the design rationale under these headings:

- **What it measures**: the capability under test and the mechanism behind it.
  For a trap, it names the wrong move and the decoy that invites it.
- **Grounding**: where each behaviour and literal comes from in parsec's source
  at `28e2c40`, cited by file and line.
- **Weighting**: why the task splits its weight between tool calls and the
  answer the way it does.
- **Invented**: every literal not taken from parsec, declared as invented.
- **The wrong answer** (on most tasks): the specific wrong answer the contract is
  built to catch, and how it scores.
- Measured probe scores, the residual partial credit a mixed answer can still
  earn, and any exemption from a discrimination floor, where they apply.

`seeds/<service>.json` is the full world the simulation answers from.
`tests/expected.json` is what gets graded. `golden.json` shows one correct path
through it.

The provenance files refer to a few authoring rules by name or number. The ones
that recur:

- **Acceptance bar.** (A) Every honest answer that answers everything asked
  scores 1.000, however it is phrased. (B) Every answer stating no true graded
  literal, such as a pure fabrication or a decoy reading, scores no higher than
  the mute probe. (C) An answer stating a true literal *and* something false may
  score above mute, and that partial credit is recorded as a measured residual.
- **A forbidden form must never contain a required form**, or the sentence meant
  to cost a fabricator a point also pays one (hazard 12).
- **A forbidden literal must not appear in the seed**, or an honest answer that
  names what it excluded is penalised (hazard 14).
- **An absence is graded as a derived fact**, since a non-finding has no seed
  literal (hazard 15).
- **Every discriminating argument of an expected call must be derivable** from
  the instruction or an earlier result. A free-text query argument is never
  pinned (hazard 19).
- **The bundle's `SKILL.md` decides which collection a tool reads** and how it
  resolves an omitted argument, so the seed goes where the simulation will look
  (hazard 20).
- **No wall-clock-relative language in an instruction** (item 3), and **every
  graded fact is something the instruction asks for** (item 4).
- **S9b** is the hand-scored adversarial probe step behind the acceptance bar.
  It scores fabricators, honest answers phrased unlike the golden, and a
  decoy-record answer through the task's own verifier.
